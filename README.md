# Упрощённая версия лабораторной
Три файла программы:
- main.hpp — классы, объявления функций и шаблоны.
- functions.cpp — реализации обычных функций.
- main.cpp — создание Manager и вызов Run(), а также обработка ошибки запуска.
Поместите их в одну папку. В проект Visual Studio добавьте оба файла .cpp и заголовок main.hpp. Старые исходники исключите из сборки: иначе появятся повторные определения функций. Стандарт C++17 подходит. В коде также достаточно возможностей C++11.
Функция main() находится в main.cpp. Заголовок main.hpp подключается через #include "main.hpp". Файлы .cpp через #include подключать не нужно.
## Что осталось от первой работы
Сохранены поля трубы и КС, класс станции A/B/C, логика ввода положительных чисел, изменение ремонта трубы, запуск и остановка одного цеха, сохранение и загрузка. Главное меню по-прежнему имеет только пункты 0–7.
| Пункт | Действие |
|---|---|
| 1 | Добавить ещё одну трубу |
| 2 | Добавить ещё одну КС |
| 3 | Выбрать просмотр всех объектов или поиск труб/КС |
| 4 | Найти трубы и управлять всеми найденными или выбранными |
| 5 | Найти КС и запустить/остановить цеха либо удалить выбранные КС |
| 6 | Сохранить все объекты |
| 7 | Загрузить все объекты |
| 0 | Выйти |
Новые вопросы находятся внутри пунктов меню. Название и параметры трубы при редактировании не меняются: по заданию редактируется признак ремонта. У КС меняется число работающих цехов.
## Почему код стал проще
Убраны map, set, лямбда-функции, отдельный класс журнала, геттеры и сеттеры. Основная работа выполняется обычными функциями и циклами.
Pipe и CompressorStation объявлены через class. Их поля находятся в public, поэтому доступ выглядит как в прежней программе:
~~~cpp
pipe.length = 10;
station.countShops = 5;
~~~
Метод CompressorStation::UnusedPercent() использует данные конкретной станции. У Manager коллекции и счётчик ID закрыты: ими управляют методы этого класса.
## Несколько объектов: vector
Раньше была одна переменная:
~~~cpp
Pipe pipe;
~~~
Теперь есть список:
~~~cpp
vector<Pipe> pipes;
~~~
Он может хранить несколько труб. Для КС используется отдельный список vector<CompressorStation>.
~~~cpp
pipes.push_back(pipe);
~~~
Добавляет заполненную трубу в конец списка.
~~~cpp
pipes[index]
~~~
Позволяет обратиться к трубе на позиции index.
~~~cpp
pipes.erase(pipes.begin() + index);
~~~
Удаляет трубу на этой позиции. Следующие элементы сдвигаются.
## ID и позиция — разные вещи
nextId хранится внутри Manager, передаётся функциям по ссылке и увеличивается после каждого добавления. Счётчик общий для труб и КС. Например: труба ID 1, КС ID 2, труба ID 3.
Поле id сохраняет номер объекта. При удалении других объектов этот номер не меняется.
Позиции в vector начинаются с нуля и могут изменяться при удалении. Поэтому нельзя использовать ID как индекс:
~~~cpp
// Для получения позиции вызываем отдельную функцию:
int index = FindIndex(pipes, id);
~~~
FindIndex перебирает список и возвращает позицию нужного объекта. Если ID отсутствует, возвращает -1.
Это простой последовательный поиск. Он подходит для небольшой учебной программы; поиск одного ID занимает O(n). Пакетные действия тоже используют обычные циклы, без дополнительных структур индексов.
## Проверка ввода и шаблон
Вместо двух почти одинаковых функций ReadInteger и ReadPositiveNumber используется:
~~~cpp
template <typename T>
T ReadNumber(const string& message, T minValue, T maxValue, bool excludeMin = false)
~~~
T заменяется конкретным типом:
~~~cpp
int command = ReadNumber<int>("Command: ", 0, 7);
double length = ReadNumber<double>("Length: ", 0.0,
    numeric_limits<double>::max(), true);
~~~
Для команды нужен int. Для длины — double. true запрещает значение нижней границы, то есть длина должна быть строго больше нуля.
numeric_limits<double>::max() — максимальное конечное значение типа double. Это не дополнительная библиотека для ввода: значение используется как верхняя граница допустимого числа.
Проверки формата и диапазона сохранены, но чтение выполняется через getline:
1. ReadLine получает всю введённую строку.
2. Она записывает её в log.txt.
3. ParseNumber пытается получить из строки одно число.
4. ReadNumber проверяет границы.
Поток istringstream нужен, чтобы разобрать уже считанную строку. Строка 2abc отклоняется, так же как в вашем варианте с cin.peek(). Дробь 2.5 отклоняется при чтении int. Пробелы после числа допускаются. Отрицательная или нулевая длина отклоняется. Слишком большое число и бесконечность тоже не принимаются.
cin.clear() и cin.ignore() теперь не нужны: каждая попытка начинается с новой строки, а преобразование производится в отдельном локальном потоке.
ReadText проверяет непустое название. ReadStationClass разрешает только A, B или C.
## Перегрузка функций
В программе есть функции с одним названием и разными параметрами:
~~~cpp
void ShowObject(const Pipe& pipe);
void ShowObject(const CompressorStation& station);
~~~
Если передана труба, компилятор выбирает первую функцию. Если КС — вторую.
Перегружены также LoadObject и операторы >> и <<.
## Перегрузка операторов
Раньше ввод трубы находился в AddPipe. Теперь в AddPipe написано:
~~~cpp
Pipe pipe;
cin >> pipe;
~~~
Компилятор вызывает функцию:
~~~cpp
istream& operator>>(istream& input, Pipe& pipe);
~~~
Для КС используется отдельная перегрузка:
~~~cpp
istream& operator>>(istream& input, CompressorStation& station);
~~~
istream& — ссылка на входной поток. Pipe& — ссылка на заполняемый объект. Возвращается тот же поток, чтобы поддерживать обычный стиль проверки и последовательного чтения.
Если передана консоль cin, функция задаёт вопросы и использует прежние проверки ReadNumber. Проверка &input == &cin сравнивает адреса потоков. Если передан другой поток, например istringstream при загрузке, вопросы не выводятся: читается сохранённая запись. При неправильной записи устанавливается failbit, а сам объект не меняется, поскольку сначала используется временная переменная.
Для записи используются:
~~~cpp
ostream& operator<<(ostream& output, const Pipe& pipe);
ostream& operator<<(ostream& output, const CompressorStation& station);
~~~
В SaveObjects выполняется file << object. Оператор записывает данные в формате файла: ID, название в кавычках и остальные поля.
Для красивого вывода пользователю оставлены ShowObject: они показывают подписи полей. Формат записи оператора << одинаков для любого выходного потока, поэтому сохранение можно проверить через ostringstream без настоящего файла.
Это уже перегрузка операторов, дополнительно к обычной перегрузке функций ShowObject.
## Менеджер и короткий main
В main.cpp содержится только создание Manager, вызов manager.Run() и обработка ошибки.
Manager хранит списки труб и КС, nextId и открытый журнал. Метод Run содержит главное меню. ManagePipes и ManageStations выполняют поиск, выбор подмножества и действие.
Программа сохраняет восемь вариантов главного меню: 0–7. В пунктах 4 и 5 отдельного поиска по ID больше нет: сначала выбирается фильтр, затем программа показывает ID найденных объектов и предлагает обработать все или выбрать отдельные.
## Остальные шаблоны
- FindIndex — ищет позицию трубы или КС по ID.
- ShowObjects — выводит список.
- ShowFound — выводит найденные объекты по списку ID.
- SelectObjects — выбирает все найденные или отдельные объекты.
- SaveObjects — сохраняет список.
- LoadObjects — загружает список.
Шаблоны находятся в main.hpp, поскольку компилятор должен видеть их определения при создании функций для конкретных типов.
## Поиск
Пункт 3 → 1 показывает все трубы и КС.
Пункт 3 → 2 предлагает поиск труб по фрагменту названия, признаку ремонта или просмотр всех труб.
Пункт 3 → 3 предлагает поиск КС по фрагменту названия, диапазону процентов незадействованных цехов или просмотр всех КС.
Поиск названия учитывает регистр: Pipe и pipe различаются.
Процент вычисляется так:
~~~cpp
100.0 * (countShops - countShopsInWork) / countShops
~~~
Например, из четырёх цехов работает один. Не работают три: 3 / 4 * 100 = 75%.
Для поиска ровно 75% укажите минимум 75 и максимум 75. Границы диапазона включаются.
## Пакетное действие
1. Выберите пункт 4 — поиск и управление трубами.
2. Найдите трубы по названию, ремонту или выберите все трубы.
3. Выберите все найденные или поочерёдный выбор.
4. При поочерёдном выборе программа спрашивает для каждого найденного ID: 1 — включить, 0 — пропустить.
5. Выберите изменение ремонта или удаление.
6. При изменении введите общий новый статус 0 или 1.
Поочерёдные вопросы позволяют выбрать любое подмножество найденных труб без сложного разбора списка ID.
Пакетное удаление опирается на ID. Перед каждым удалением позиция находится заново, потому что после erase позиции следующих элементов меняются.
## Логирование
Технический журнал записывается через стандартный поток clog. Менеджер открывает log.txt один раз в режиме ios::app и перенаправляет туда clog:
~~~cpp
oldLogBuffer = clog.rdbuf(logFile.rdbuf());
~~~
rdbuf() — буфер потока, то есть то, куда поток передаёт символы. После перенаправления сообщения clog попадают в log.txt. При завершении Manager возвращает прежний буфер, пока файл ещё открыт.
Обычный cout продолжает выводить меню в консоль. clog используется для отладки.
Для удобства в заголовке определён макрос:
~~~cpp
#define LogAction(message) WriteLog(__FILE__, __LINE__, __func__, message)
~~~
Он добавляет к сообщению:
- __FILE__ — имя исходного файла;
- __LINE__ — номер строки вызова;
- __func__ — имя функции.
WriteLog добавляет дату и время. Например, запись имеет такой вид:
~~~text
2026-11-01 12:30:00 | functions.cpp:368 | ManagePipes | Batch edit pipe ID=1 old=0 new=1
~~~
Дата и номер строки в примере условные: настоящие значения зависят от времени запуска и версии файла.
Такая запись помогает найти участок кода и увидеть старое и новое значения. Это отличается от одного сообщения «труба изменена».
В журнал попадают весь ввод, ошибки проверки, команды, результаты поиска и выбора, добавления, изменения, удаления, сохранение, загрузка и завершение программы. У КС фиксируется старое и новое количество работающих цехов. Отказ запустить/остановить цех тоже записывается.
Макрос не создаёт отдельный класс и позволяет сохранить короткую запись LogAction("сообщение"). Это единственный служебный макрос, помимо #pragma once.
Закрытие ввода обрабатывается в Manager::Run, чтобы main оставался коротким. При невозможности открыть или записать журнал программа сообщает об ошибке.
## Сохранение и загрузка
Имя файла вводится пользователем, например data.txt или network.txt. В этой упрощённой версии вводится только имя, без пути к папке. Файл создаётся в рабочей папке программы.
ReadFilename не разрешает использовать log.txt для данных, в том числе при записи имени большими буквами. Иначе журнал мог бы быть стёрт.
Сохранение заменяет содержимое указанного файла. Автоматического сохранения при выходе нет.
Формат GAS_TRANSPORT_V2 сохранён от предыдущей многoобъектной версии. В файл записываются следующий ID, количество труб, трубы, количество КС и КС. quoted сохраняет названия с пробелами и кавычками. setprecision обеспечивает достаточную точность чисел double.
Старые файлы самой первой лабораторной, где хранились одна труба и одна КС без ID, имеют другой формат.
При загрузке данные сначала проверяются во временных списках:
- ID положительные и не повторяются;
- следующий ID больше всех загруженных;
- длина и диаметр положительные и конечные;
- ремонт равен 0 или 1;
- количество работающих цехов от нуля до общего количества;
- класс станции A, B или C;
- названия непустые, файл имеет правильный формат.
Эти проверки оставлены, чтобы повреждённый файл не нарушил условия задания. Только после них данные заменяют текущие списки.
## Проверка
Программа собрана Microsoft Visual C++ без предупреждений с /W4. Проверены меню 0–7, несколько объектов, ID, поиск, выбор подмножества, пакетные действия, ограничения цехов, сохранение и загрузка через перегруженные операторы, технический журнал и закрытие ввода. Повреждённый файл не заменяет текущие объекты.
